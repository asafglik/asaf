# מעצב טפסים ושרת הפקת PDF

מערכת לעיצוב תבניות של טפסים ולהפקת קובצי PDF מנתוני XML או JSON.

* **ניהול תבניות** (מסך הפתיחה, `/`) – רשימת התבניות עם חיפוש, עריכה, שכפול, מחיקה, ייצוא ושיוך ללקוחות. לכל לקוח אפשר להגדיר מפתח API משלו ולהוריד חבילת התקנה.
* **מעצב (Designer)** (`/designer.html`) – אפליקציית דפדפן לבניית תבנית: טקסט קבוע, שדות נתונים, שדות מחושבים, טבלאות, תמונות, ברקודים ו-QR, טקסט מעוצב כמו ב-Word, אזורי חתימה והעלאת תמונה, כותרת עליונה ותחתונה, תנאי הצגה, קווים ומסגרות. בונים כל תבנית על **עולם נתונים** (דוגמת XML או JSON). אפשר גם ליצור תבנית מקובץ **PDF** או **Word**.
* **סוכן עיצוב חכם** – אחרי העלאת PDF דוגמה, הסוכן ממקם לבד את השדות, הטבלאות ואזורי החתימה, או בונה את המסמך מחדש. אפשר גם לבקש ממנו שינויי עיצוב במילים.
* **שרת הפקה (Render server)** – מקבל **מספר תבנית** ונתונים **באותו מבנה** של עולם הנתונים, ומחזיר PDF. אפשר להתקין אותו בשרת של הלקוח, כולל מצב "הפקה בלבד" בלי המעצב.

```
 מערכת קוראת (Caché/IRIS, ‎.NET, Java...)                 שרת הפקה
 ─────────────────────────────────────       POST /api/render/1001       ┌──────────────────────────┐
  <invoice>...</invoice>  או  {...}   ───────────────────────────────▶   │ storage/templates/1001.json│
                                       ◀───────────────────────────────   │ Chrome ללא ממשק → PDF      │
                         application/pdf                                  └──────────────────────────┘
```

## התקנה והרצה

דרישות:

* Node.js בגרסה 18 ומעלה.
* דפדפן Chrome, Chromium או Edge בשרת. השרת מאתר אותו לבד, או לפי `CHROME_PATH`.
* LibreOffice – רשות. נדרש רק לייבוא Word "כפריסה מדויקת".

```bash
cd form-designer
npm install
npm start                # מעצב + API  →  http://localhost:3700
```

אם אין דפדפן בשרת: `npx puppeteer browsers install chrome`. אחר כך מגדירים את `CHROME_PATH` לנתיב שהפקודה מדפיסה. האפשרות השנייה היא להתקין Chrome או Edge רגיל.

תבנית לדוגמה (#1001, חשבונית מס) כבר נמצאת ב-`storage/templates`. הנתונים שלה נמצאים ב-`examples/invoice.xml`.

### התקנה בשרת לקוח (הפקה בלבד)

1. מעתיקים לשרת את תיקיית `form-designer` בלי `node_modules`.
2. מריצים `npm install --omit=dev`.
3. מעתיקים את קובצי התבניות (`storage/templates/<מספר>.json`). כל תבנית היא קובץ אחד שמכיל הכול: תמונות וקובץ PDF מקור. גופנים שהועלו נמצאים ב-`storage/fonts` ומעתיקים גם אותם.
4. מריצים `npm run start:render`, או `FD_MODE=render`.

במצב `render` אין ממשק עיצוב ואין API לשינוי תבניות. רק הפקה, צפייה ברשימת התבניות ובדיקת מצב (`/api/health`).

**Windows כשירות:** למשל עם [NSSM](https://nssm.cc):
`nssm install FormRender "C:\Program Files\nodejs\node.exe" "C:\form-designer\server\index.js --mode=render"`.
מגדירים בשירות את משתני הסביבה (`PORT`, `FD_API_KEY`) לפי הצורך.
**Linux:** שירות systemd עם `ExecStart=/usr/bin/node /opt/form-designer/server/index.js --mode=render`.

### הגדרות

משתני סביבה, או קובץ `config.json` (ראו `config.example.json`):

| משתנה | config.json | ברירת מחדל | תיאור |
|---|---|---|---|
| `PORT` | `port` | `3700` | פורט |
| `HOST` | `host` | `0.0.0.0` | כתובת האזנה |
| `FD_MODE` / `--mode=` | `mode` | `full` | `full` = מעצב + הפקה, `render` = הפקה בלבד |
| `FD_STORAGE` | `storageDir` | `storage` | תיקיית התבניות והגופנים |
| `CHROME_PATH` | `chromePath` | איתור אוטומטי | נתיב ל-chrome.exe / msedge.exe / chromium |
| `FD_API_KEY` | `apiKey` | ריק | אם מוגדר, כל קריאה ל-`/api` חייבת לכלול כותרת `x-api-key` |
| `FD_MAX_CONCURRENT` | `maxConcurrent` | `4` | מספר הפקות במקביל |
| `FD_BODY_LIMIT` | `bodyLimit` | `60mb` | גודל בקשה מרבי |
| `FD_ALLOW_REMOTE_IMAGES` | `allowRemoteImages` | `false` | לאפשר תמונות מכתובות http(s) בנתונים |
| `SOFFICE_PATH` | `sofficePath` | איתור אוטומטי | נתיב ל-LibreOffice |
| `ANTHROPIC_API_KEY` | `anthropicApiKey` | ריק | מפתח Claude API לסוכן העיצוב החכם. בלי מפתח זמין רק זיהוי בסיסי |
| `FD_AI_MODEL` | `aiModel` | `claude-opus-5-5` | המודל שהסוכן משתמש בו |
| `FD_RENDER_TIMEOUT_MS` | `renderTimeoutMs` | `60000` | זמן מרבי להפקת מסמך |
| `FD_MAX_QUEUE` | `maxQueue` | `100` | מספר בקשות מרבי בתור. מעבר לזה השרת עונה 503 |
| `TZ` | `timeZone` | `Asia/Jerusalem` | אזור הזמן לתאריכים (`today()`, עיצוב תאריך) |

> **מפתחות API:** `FD_API_KEY` הוא מפתח המנהל: הוא נותן גישה לכל המערכת. לכל לקוח אפשר להגדיר במסך הניהול מפתח משלו (16 תווים לפחות). עם מפתח לקוח אפשר רק לראות ולהפיק את התבניות ששויכו לאותו לקוח, ואין גישה למעצב.
> * מפתחות לקוח נשמרים רק כ-hash. המפתח עצמו מוצג פעם אחת, ביצירה.
> * חבילת ההתקנה כוללת את ה-hash, כך שגם בשרת הלקוח המפתח עובד.
> * בשרת הפקה (`render`) עם מפתחות לקוח, חייבים לשלוח מפתח בכל בקשה.
> * המפתח נשלח רק בכותרת `x-api-key`. מפתח בכתובת (`?apiKey=`) לא מתקבל.
>
> **אבטחת ההפקה:**
> * בדפדפן ההפקה JavaScript כבוי, ואין לו גישה לרשת (גם לא WebSocket או רשת פנימית).
> * כל ערך נתונים עובר escaping.
> * ערכי עיצוב (צבע, גופן וכו') מנוקים מתווים שיכולים לשבור את ה-CSS.
> * טקסט מעוצב מנוקה לרשימה מותרת של תגיות.
> * להפקה יש זמן מרבי (`FD_RENDER_TIMEOUT_MS`, ברירת מחדל 60 שניות) ותור מוגבל (`FD_MAX_QUEUE`). מעבר לתור השרת עונה 503.
>
> **אבטחה:** אין במעצב מנגנון משתמשים. מריצים אותו ברשת פנימית, או מגדירים `FD_API_KEY`. המעצב מבקש את המפתח פעם אחת ושומר אותו בדפדפן. בזמן ההפקה הדפדפן חוסם כל גישה לרשת (חוץ מתמונות, אם הותרו), וכל ערך מהנתונים עובר escaping.

## עבודה במעצב

1. **עולם נתונים** – לוחצים "עולם נתונים", מדביקים דוגמת XML או JSON או טוענים קובץ. מבנה הנתונים מופיע בלשונית **נתונים**.
2. **רכיבים** – גוררים רכיב מהסרגל לדף, או לוחצים עליו כדי להוסיף אותו.
   * גרירת **שדה** מעולם הנתונים יוצרת שדה נתונים.
   * גרירת **רשימה** (☰) יוצרת טבלה עם עמודות.
   * לחיצה על שדה בעץ מקשרת אותו לרכיב שנבחר.
3. **מאפיינים** – הלוח השמאלי. אפשר לערוך מיקום וגודל במ"מ, גופן, גודל, צבע, יישור, כיוון, מסגרת, רקע, עיצוב ערכים ותנאי הצגה.
4. **תצוגה מקדימה PDF** – מפיקה PDF אמיתי בשרת עם נתוני הדוגמה, או עם נתונים אחרים שמדביקים בחלון.
5. **שמירה** – שומרים לפי **מספר תבנית**. זה המספר שהמערכת הקוראת שולחת.

### סוגי רכיבים

| רכיב | מה עושה |
|---|---|
| טקסט קבוע | טקסט רגיל. אפשר לשלב בו שדות: `לכבוד {{customer.name}}` |
| שדה נתונים | ערך מהנתונים, עם עיצוב (מספר, מטבע, תאריך...), טקסט לפני ואחרי, וטקסט כשאין ערך |
| שדה מחושב | נוסחה, למשל `sum(items.item, price * qty) * 1.18` |
| טקסט מעוצב | עריכה כמו ב-Word (לחיצה כפולה): גופנים, גדלים, צבעים, יישור, רשימות, טבלאות, שדות. אפשר להמשיך אותו בעמודים הבאים |
| טבלה | נבנית מרשימה בנתונים. לכל עמודה: שדה או ביטוי, עיצוב, יישור ושורת סיכום. אפשר גם תא מסוג תמונה או ברקוד, סינון, מיון והדגשת שורות. **טבלה ארוכה ממשיכה בעמוד חדש** והכותרת חוזרת |
| תמונה | קובץ קבוע (נשמר בתוך התבנית), או מהנתונים: Base64 או כתובת |
| ברקוד / QR | Code128, Code39, EAN-13/8, UPC-A, ITF-14, GS1-128, QR, DataMatrix, PDF417, Aztec. הערך יכול להיות קבוע, שדה או ביטוי |
| תיבת סימון | מסומנת כשהערך הוא true / 1 / Y / כן / X |
| אזור חתימה | מקום לחתימה, עם קו ותווית. יש לו **שם placeholder** ייחודי, ואפשר להגדיר חותם ושדה חובה. אם בנתונים יש תמונת חתימה (Base64), היא מודפסת במקום |
| אזור העלאת תמונה | מסגרת מקווקוות למקום שבו תועלה תמונה, למשל צילום תעודה. גם לו יש שם placeholder ייחודי |
| שדה למילוי (טקסט / תאריך / תיבת סימון) | מקום שממלאים אחרי ההפקה: קו עם תווית, תאריך (`__/__/____`) או תיבה לסימון עם טקסט. יש לו שם placeholder ייחודי, ואפשר למלא אותו מראש משדה בעולם הנתונים |
| קו, מלבן, אליפסה | עיצוב גרפי |

### יישור, הצמדה ושוליים

* **הצמדה חכמה:** בזמן גרירה או שינוי גודל, הרכיב נצמד לקצוות ולמרכז של רכיבים אחרים, לשולי הדף ולמרכז הדף. קו עזר אדום מראה למה הוא נצמד. החזקת Alt מאפשרת גרירה חופשית. אפשר לכבות את ההצמדה בהגדרות "שוליים, רשת והצמדה".
* **שולי הדף:** מגדירים שוליים (ימין, שמאל, למעלה, למטה) במאפייני התבנית. הם מוצגים כקו מקווקו, ורכיבים נצמדים אליהם.
* **כלי יישור** (בלוח המאפיינים):
  * **כמה רכיבים:** הצמדה לימין, לשמאל ולמרכז (אופקי ואנכי), ביחס ל**בחירה**, ל**רכיב הראשון שנבחר** (מסומן בכתום) או ל**שולי הדף**. בנוסף: אותו רוחב או גובה, ופיזור אופקי או אנכי במרווחים שווים.
  * **רכיב אחד:** יישור לשולי הדף, ו"רוחב מלא" בין השוליים.
* חיצים מזיזים את הרכיב ב-1 מ"מ (עם Shift ב-5 מ"מ, עם Alt ב-0.1 מ"מ).

### ריבוי שפות

תבנית אחת יכולה להודפס בכמה שפות: עברית, אנגלית, ערבית, רוסית, צרפתית ואמהרית.

* **הגדרה:** במאפייני התבנית, בקבוצה "שפות", בוחרים את שפת ברירת המחדל ואת השפות הנוספות. ליד כל שפה מופיע כמה טקסטים חסר לה תרגום.
* **עריכת תרגום:** בוחרים שפה ברשימה בסרגל העליון. הדף מוצג בשפה שנבחרה, ושדות הטקסט בלוח המאפיינים (טקסט, טקסט מעוצב, כותרות עמודות, תוויות, לפני ואחרי) נערכים בשפה הזו. שדה שעוד לא תורגם מודפס בשפת ברירת המחדל.
* **תרגום אוטומטי:** כפתור "תרגום אוטומטי" מתרגם בעזרת הסוכן החכם את כל הטקסטים החסרים. שדות `{{...}}` נשמרים כמו שהם.
* **שפה בכיוון השני:** כשמדפיסים באנגלית תבנית שנבנתה בעברית, כיוון הכתיבה והיישור מתהפכים, וגם הטבלאות מתהפכות. במצב "שיקוף הדף" (ברירת המחדל) גם מיקומי הרכיבים משתקפים, כך שהמסמך נראה כמו מסמך שנכתב באנגלית מלכתחילה. בעמודים עם רקע PDF המיקומים נשארים כמו במקור. אם רכיב מסוים צריך להישאר במקומו, מגדירים לו `mirror: false`.
* **תאריכים ומספרים** מעוצבים לפי השפה. לדוגמה, ב-`date:d MMMM yyyy` יוצא "12 November 2026" באנגלית, ו-`bool` מחזיר Yes/No.
* **בתנאים:** `$lang` היא שפת ההדפסה, למשל: הצג רק אם `$lang == "en"`.
* **בהפקה:** `POST /api/render/1001?lang=en`, או `"lang": "en"` בגוף הבקשה. בשורת הפקודה: `--lang en`. בחלון התצוגה המקדימה יש בחירת שפה.

תבנית הדוגמה 1001 מתורגמת לאנגלית.

### הדרכה

לחיצה על הכפתור **? הדרכה** בסרגל העליון, במעצב ובמסך הניהול, פותחת סיור מודרך על חלקי המסך. הסיור נפתח גם לבד בכניסה הראשונה. מקשים: ← הבא, → הקודם, Esc יציאה.

### גרירה מעולם הנתונים

* **גרירה לשטח ריק בדף:**
  * גרירת שדה יוצרת שדה נתונים.
  * גרירת רשימה (☰) יוצרת טבלה.
  * גרירת שדה מתוך רשימה יוצרת שדה של הפריט הראשון ברשימה.
* **גרירה על רכיב קיים** (הרכיב מסומן בירוק בזמן הגרירה):
  * על טבלה: מוסיפה עמודה.
  * על טקסט: מוסיפה `{{שדה}}` לטקסט.
  * על שדה, ברקוד, תמונה או אזור חתימה: מקשרת אותו לנתון.
* **לחיצה כפולה** על שדה בעץ מוסיפה אותו לדף.

### תנאי הצגה והסתרה

כל רכיב (שדה, טקסט, תיבה, טבלה, אזור חתימה וכו') יכול להופיע רק כשתנאי מתקיים. בלוח המאפיינים, בקבוצה **"הצגה והסתרה"**:

* **בונה תנאים:** בוחרים שדה, פעולה וערך. הפעולות: שווה, שונה, גדול, קטן, מכיל, ריק, לא ריק, מסומן. אפשר לחבר כמה תנאים עם "וגם" או "או".
* **ביטוי מתקדם:** ביטוי חופשי, למשל `customer.vip == true and total > 1000`.
* במעצב, רכיב שמוסתר לפי נתוני הדוגמה מסומן בפסים.

### כותרת עליונה ותחתונה

בלשונית **עמודים** (או בתפריט ⋯) בוחרים "כותרת עליונה" או "כותרת תחתונה" ועורכים אותן כמו עמוד רגיל: לוגו, טקסט, `{{page}}`, אזורי חתימה ועוד.

* הכותרות מודפסות **בכל עמוד** במסמך, כולל עמודי המשך של טבלאות ארוכות.
* בהגדרות הכותרת קובעים את הגובה, ואם להציג אותה בכל העמודים, רק בראשון, בכולם מלבד הראשון וכו'.
* בעמודים הרגילים הכותרות מוצגות בשקיפות. לחיצה כפולה עליהן פותחת אותן לעריכה.

### אזורי מילוי, חתימה ותמונה ב-API

לכל אזור חתימה, העלאת תמונה או שדה למילוי (טקסט, תאריך, תיבת סימון) יש שם (placeholder). במעצב מגדירים לכל אזור גם נתונים שלא מודפסים: **כותרת ראשית**, **כותרת משנית**, **חובה / לא חובה** ו**תיאור**.

המערכת מחזירה לכל אזור:

* `name`, `type` (`signature` / `upload` / `input`), `kind` (`signature` / `upload` / `text` / `date` / `checkbox`).
* `title`, `subtitle`, `description`, `required`, `label` (התווית שמודפסת), `signer` (לחתימה), `format` (לתאריך).
* בהפקה גם הערך שהתקבל מעולם הנתונים: `value` (טקסט, תאריך מעוצב, או `true`/`false` לתיבת סימון) ו-`filled` (האם האזור כבר מולא, כולל תמונת חתימה מהנתונים).
* העמוד, המיקום (X, Y) והגודל.

המיקום ניתן בשתי צורות:

* `mm` – מילימטרים מהפינה השמאלית **העליונה** של הדף.
* `pdf` – נקודות PDF מהפינה השמאלית **התחתונה**, כמו שספריות חתימה דיגיטלית מצפות.

איפה מקבלים את המידע:

* **בשמירת תבנית:** התשובה ל-`POST /api/templates` ול-`PUT /api/templates/{id}` כוללת שדה `placeholders`.
* **בכל זמן:** `GET /api/templates/{id}/placeholders`.
* **בהפקה:** עם `output=json` (או `base64`) התשובה כוללת את המיקומים בפועל במסמך שהופק. המיקום כבר משקף מעבר עמודים, תנאי הצגה וכותרות שחוזרות בכל עמוד.
  * כשאזור מופיע ביותר מעמוד אחד (בכותרת, או בעמודי המשך), השם שלו בכל עמוד נוסף מקבל סיומת: `stamp`, `stamp_p2`, `stamp_p3`.
  * השם המקורי נשמר בשדה `baseName`.
  * כך כל שם ברשימה ייחודי, כמו שספריות חתימה דורשות.

* **בתוך ה-PDF:** כל PDF שיש בו אזורים כולל קובץ מצורף `placeholders.json` עם אותה רשימה, כך שגם מי שמקבל רק את הקובץ יודע איפה לחתום ומה למלא.

```json
{ "name": "delivery_date", "type": "input", "kind": "date", "title": "תאריך מסירה", "subtitle": "", "description": "",
  "required": true, "label": "תאריך", "format": "dd/MM/yyyy", "value": "13/11/2026", "filled": true, "page": 1,
  "mm":  { "x": 60, "y": 35, "width": 40, "height": 11 },
  "pdf": { "x": 170.08, "y": 711.5, "width": 113.39, "height": 31.18 } }
{ "name": "customer_signature", "type": "signature", "kind": "signature", "title": "חתימת הלקוח", "subtitle": "בעת קבלת הרכב",
  "description": "חתימה מלאה", "required": true, "signer": "לקוח", "filled": false, "page": 2,
  "mm":  { "x": 12, "y": 262, "width": 60, "height": 16 },
  "pdf": { "x": 34.02, "y": 51.02, "width": 170.08, "height": 45.35 } }
```

### חוות דעת על טופס קיים

בלשונית **סוכן ✨** → "העלאת PDF לחוות דעת" מעלים PDF שהמערכת הנוכחית הפיקה מ**אותו עולם נתונים** (אותה רשומה שנטענה כנתוני הדוגמה). מתקבל דוח עם:

* **ציון ותקציר.**
* **התאמת שדות:** כל ערך שהודפס בקובץ מחופש בעולם הנתונים. המערכת מזהה את הערך גם בפורמט אחר, למשל תאריך `20250123` שהודפס כ-23/01/2025, `55` שהודפס כ-55.0, או ערך שנשבר לשתי שורות.
  * לכל ערך מזוהים הנתיב בעולם הנתונים, התווית שלידו בטופס (מימין, מעל או מתחת), והמיקום שלו.
  * כשאותו ערך קיים בכמה שדות (למשל צמיג קדמי ואחורי), בוחרים את הנכון מרשימה.
* **טבלאות:** שורות שמקורן באותה רשימה בנתונים מזוהות כטבלה, כולל העמודות, שדה הנתונים של כל עמודה והכותרות.
* **מה כדאי לשפר:** ממצאים אוטומטיים, לדוגמה:
  * טקסט קטן מדי, ויותר מדי גדלי גופן.
  * תאריכים ומספרים שנשברים לשתי שורות.
  * פורמטים לא עקביים, ".0" מיותר בכמויות.
  * כוכביות של Code39 בטקסט הברקוד.
  * תוויות בלי ערך.
  * שורות טבלה ריקות.
  * כותרת שחוזרת במלואה בכל עמוד, ועמודים כמעט ריקים.
  * שדות חשובים בנתונים שלא מוצגים בטופס.
* **עם הסוכן החכם** (מפתח Claude בשרת) מתווספים ביקורת עיצובית לפי תמונות העמודים, הצעדים עם ההשפעה הגדולה ביותר, ותיקון של שדות לא חד-משמעיים לפי משמעות התווית.

פעולות מהדוח:

* **בנייה כתבנית מעוצבת:** הטופס נבנה מחדש מרכיבים:
  * טקסטים בגודל ובמשקל המקוריים, וקווים ומסגרות.
  * שדות מקושרים לעולם הנתונים במקום הערכים.
  * טבלאות דינמיות עם מעבר עמודים, במקום שורות קבועות.
  * כותרת עליונה, אם הכותרת חזרה בכל העמודים.
  * "עמוד X מתוך Y" כמספור עמודים חי.
  * ברקוד שמקושר לשדה.
* **שדות מעל ה-PDF:** הקובץ נשאר רקע, והשדות (עם רקע לבן) מונחים בדיוק על הערכים שהודפסו.
* **✨ עיצוב משופר עם הסוכן:** הסוכן בונה עיצוב חדש לפי חוות הדעת ולפי התאמת השדות.

ב-API: `POST /api/ai/review` עם `{ pages, template | data }`. מבנה `pages` הוא הפלט של `shared/pdfanalyze.js` (טקסטים, מיקומים, גדלים, קווים).

### סוכן העיצוב החכם

הסוכן נמצא בלשונית **סוכן ✨** במעצב.

* **עיצוב אוטומטי מקובץ דוגמה:** מעלים PDF דוגמה, או משתמשים ב-PDF שכבר בתבנית. הסוכן מקבל את תמונת העמודים, את הטקסטים ומיקומם, את שדות הטופס הקיימים ב-PDF ואת עולם הנתונים. יש שני מצבים:
  * **שדות מעל ה-PDF:** ה-PDF נשאר רקע, והסוכן ממקם שדות, טבלאות, תיבות סימון ואזורי חתימה בדיוק במקומות הריקים.
  * **בנייה מחדש:** המסמך נבנה מחדש מרכיבים (טקסטים, גופנים, קווים, טבלאות), בלי רקע.
* **בקשות עיצוב:** כותבים בעברית מה לשנות, למשל "הגדל את הכותרת והדגש אותה", "הוסף כותרת תחתונה עם מספרי עמודים" או "הצג את ההערות רק כשיש בהן תוכן". הסוכן רואה את העמוד כפי שהוא מעוצב כרגע ומבצע את השינוי.
* כל תשובה של הסוכן מתבצעת כפעולה אחת, וכפתור "ביטול" (או `Ctrl+Z`) מחזיר את המצב הקודם.
* הסוכן משתמש ב-Claude (Anthropic API). מגדירים `ANTHROPIC_API_KEY` בשרת המעצב (לא נדרש בשרתי ההפקה).
  * ה-PDF, תמונות העמודים ומבנה הנתונים נשלחים ל-API של Anthropic.
  * כשהמודל מסרב לבקשה, היא עוברת אוטומטית למודל חלופי (server-side fallback).
* **בלי מפתח** פועל **זיהוי בסיסי**: שדות טופס קיימים ב-PDF, תוויות שמסתיימות בנקודתיים ("שם:"), "חתימה" ו"צילום". הזיהוי מקשר אותם לשדות בעולם הנתונים לפי השם.

### ביטויים ושדות בטקסט

* **נתיבים:** `customer.name`, `items.item[0].price`, `order["first-name"]`. ב-XML, מאפיין נכתב עם `@`: `@number`.
* **שמות עם מקף או רווח:** בשדה מקושר אפשר לכתוב את הנתיב כמו שהוא, למשל `customer.first-name`. כשגוררים או מוסיפים שדה כזה לטקסט, המעצב כותב אותו לבד כ-`customer["first-name"]`.
* **בטבלה:** שמות שדות מתייחסים לשורה הנוכחית. `$row` הוא מספר השורה, ו-`$rows` (בשורת הסיכום) הוא כל השורות.
* **אופרטורים:** `+ - * / %`, `== != < > <= >=`, `and or not`, `? :`, ושרשור עם `&`.
* **פונקציות:**
  * חישוב: `sum, avg, min, max, count, round, floor, ceil, abs`
  * תנאים: `if, coalesce, isEmpty`
  * טקסט: `concat, upper, lower, trim, len, left, right, substr, replace, padLeft, contains, join`
  * תאריכים: `today, now, date, addDays, addMonths, diffDays, year, month, day, age`
  * עיצוב: `format`
  * לכל פונקציית צבירה אפשר להעביר ביטוי שמחושב לכל פריט: `sum(items.item, price * qty)`.
* **בטקסט:**
  * שדה: `{{customer.name}}`
  * חישוב: `{{price * qty | currency}}`
  * תאריך: `{{date | date:dd/MM/yyyy}}`
  * מספרי עמודים: `{{page}}` ו-`{{pages}}`
* **עיצובים:**
  * מספרים: `number:2`, `plain:2`
  * מטבע: `currency` (ש"ח), `currency:USD`
  * אחוזים: `percent:1` לשבר (0.17 → 17%), `pct:1` לערך שכבר באחוזים (17 → 17%)
  * תאריך ושעה: `date:d MMMM yyyy`, `datetime`, `time`, `hdate`, `htime`
  * עברית הפוכה: `visual`
  * טקסט: `upper`, `lower`
  * ערך בוליאני: `bool:כן/לא`

### מעבר עמודים

כשטבלה (או טקסט מעוצב שהוגדר "להמשיך בעמוד הבא") לא נכנסת בתיבה שלה, המערכת מוסיפה **עמוד המשך**. עמוד ההמשך הוא העתק של אותו עמוד בתבנית, עם השורות הבאות.

* אפשר כמה טבלאות ארוכות באותו עמוד. כל אחת ממשיכה בעמודי ההמשך, ומספר העמודים נקבע לפי הארוכה מביניהן.
* טקסט מעוצב (גם מסמך Word מיובא) מתחלק בין פסקאות, פריטי רשימה ושורות טבלה.
* תוכן שלא נכנס גם בעמוד שלם (למשל שורה גבוהה מהתיבה) נחתך, ומופיעה אזהרה בתשובת ההפקה.

* אפשר לקבוע לעמוד ההמשך מיקום וגובה אחרים לטבלה (`Y בעמוד המשך`, `גובה בעמוד המשך`).
* לכל רכיב יש הגדרה **"הצג ב"**: כל העמודים, עמוד ראשון בלבד (למשל פרטי הלקוח), עמוד אחרון בלבד (למשל סיכומים וחתימה), כל העמודים מלבד הראשון, או כל העמודים מלבד האחרון.
* שורת הסיכום של הטבלה מופיעה רק בסוף הטבלה.

### יצירת תבנית מ-PDF או Word

* **PDF** – כל עמוד הופך לעמוד בתבנית. העמוד המקורי מונח כרקע **וקטורי** מתחת לתוכן שמוסיפים (חד, בלי איבוד איכות). מתאים לטפסים קיימים: מוסיפים שדות מעל המקומות הריקים.
* **Word כפריסה מדויקת** – ממיר ל-PDF עם LibreOffice בשרת, ומשם ממשיך כמו PDF.
* **Word כטקסט לעריכה** – התוכן (כותרות, הדגשות, רשימות, טבלאות ותמונות) נכנס לרכיב טקסט מעוצב. אפשר לערוך אותו ולשלב בו `{{שדות}}`, והוא ממשיך לעמודים הבאים.

### גופנים

המערכת כוללת גופנים פתוחים עם עברית: Heebo, Rubik, Assistant, Noto Sans/Serif Hebrew, Alef, Varela Round, Secular One, Suez One, Frank Ruhl Libre, David Libre, Miriam Libre ועוד.

## כללי המרת XML

* אלמנט השורש **מושמט**: ב-`<invoice><customer>...` הנתיב הוא `customer.name`.
* מאפיינים נשמרים כ-`@name`. אם לאלמנט יש גם מאפיינים וגם טקסט, הטקסט נמצא ב-`#text`, וגם `name` לבדו מחזיר את הטקסט.
* אלמנט שחוזר על עצמו הופך לרשימה (`items.item`). הנתיבים שזוהו כרשימות בדוגמה נשמרים בתבנית (`schema.arrays`), ולכן הם נשארים רשימות גם כשמגיע פריט אחד.
* הערכים נשמרים כטקסט, כך שאפסים מובילים לא נמחקים (`00123`). בחישובים הם מומרים למספרים.

## נתונים ממערכות ותיקות (Caché / IRIS)

| מצב בנתונים | איך מטפלים |
|---|---|
| קידוד `WINDOWS-1255` (או ISO-8859-8) | מזוהה לבד: לפי הכותרת `<?xml ... encoding=...?>`, לפי `charset` בכותרת ה-HTTP, ואם הקובץ אינו UTF-8 תקין – windows-1255. עובד ב-API, בשורת הפקודה ובטעינת קובץ במעצב |
| תאריך `$H` של Caché (`66524`) | פורמט `hdate`, או הפונקציה `hdate(x)` → ‏19/02/2023 |
| שעה בשניות מחצות (`57889`) | פורמט `htime`, או הפונקציה `htime(x)` → ‏16:04 |
| תאריך `14052023` (ddMMyyyy) | מזוהה לבד בכל פורמט `date` |
| תאריך במבנה אחר (`250415` = yyMMdd) | `date:dd/MM/yyyy<yyMMdd`, או `date(x, "yyMMdd")` |
| עברית שנשמרה הפוכה ("95 ןיזנב -קלד לכימ") | פורמט `visual`, או הפונקציה `visual(x)` → "מיכל דלק- בנזין 95". מספרים ומילים באנגלית שומרים על הכיוון שלהם |

## מבנה הפרויקט

```
form-designer/
├── server/            שרת Express, אחסון (תבניות ולקוחות), ניתוח נתונים, גופנים, ברקודים, ייבוא Word, סוכן העיצוב (ai.js)
│   └── render/        בניית HTML, חלוקה לעמודים בדפדפן, Chrome → PDF, מיזוג רקע PDF (pdf-lib)
├── shared/            קוד משותף לשרת ולמעצב: שפת הביטויים, עיצוב ערכים, בניית HTML של הרכיבים
├── public/            מסך הניהול (index.html) והמעצב (designer.html), HTML/CSS/JS ללא שלב בנייה
├── cli/               render.js – הפקה משורת הפקודה; import-bundle.js – התקנת חבילת לקוח
├── clients/           דוגמאות קריאה: ObjectScript, C#, PowerShell
├── examples/          נתוני דוגמה ותבנית 1001
├── storage/templates  קובצי התבניות (‎<מספר>.json) והיסטוריית גרסאות
└── test/              בדיקות (npm test)
```

המעצב והשרת משתמשים **באותו קוד** כדי לבנות את ה-HTML של כל רכיב (`shared/elements.js`), ולכן מה שרואים במעצב הוא מה שמודפס. מידות נשמרות במ"מ וגדלי גופן בנקודות (pt).
